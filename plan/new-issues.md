# Where nmr's promise can break down

## Resolve these before asking someone to share a name

1. **The first worked example disagrees with the format fixture.** The README introduces the birthday `2000-02-29` as `date:this been`. The fixture used to check both encoding and decoding gives `date:or each`. The README's fraction and chess examples also differ from their fixtures. Someone trying the very first command has no way to tell which result to trust. Check published examples against the same fixtures used for format changes. [README](../README.md) · [Format examples](../test/format.json) · [Fixture checks](../test/test_format.py)

2. **The advertised browser journey has no entry point.** The README invites someone to type a tune or open a link containing `?desc=Tom+Ritchford`, and describes three radio buttons. The page reads `mode` and `value`, defaults to Clock, and cycles modes through the heading. Its Name editor accepts vocabulary words. Someone arriving with a birthday and someone arriving with its truename need different directions. Decide which journey the site should offer, then walk both from the published instructions. [README](../README.md) · [Page and controls](../nmr/web/index.html) · [URL handling](../nmr/web/app.js) · [Current help](../nmr/web/help.md)

3. **Matching vocabulary IDs can still yield different birthdays.** The fingerprint covers word order, case policy and the bundled article rule. Both date-centering settings use that same fingerprint. For example, the local date index zero means 2027-01-01 with centering and 0001-01-01 without it. A recipient can pass the vocabulary check and confidently read the wrong date. Decide what information a sender must supply when departing from the defaults. [Vocabulary identifier](../nmr/words.py) · [Temporal mapping](../nmr/types/temporal.py) · [Decode contract](../nmr/nmr.py)

4. **A browsed discovery and a canonical name can look equally authoritative.** Count at index 86401 scoped to Time shows 00:00:01 by wrapping. Index 1 already names that second. Keeping 86401 is useful for iteration. Reusing its words as a strict Time name fails. At the point of sharing, can a visitor tell whether they are sending the object, the position in Count, or the music still finishing from a previous selection? Ask them to send that second to someone using the CLI. [Count contracts](../test/test_count.py) · [Browser smoke case](../test/browser_smoke.cjs) · [Playback help](../nmr/web/help.md)

## Decide what “all” and “the same” mean

5. **Different types preserve different kinds of identity.** Fractions preserve the entered pair, so 2/4 and 1/2 differ. Locations deliberately round to a grid, and transposing a tune preserves its name. ISBN-10 and its corresponding 978 ISBN-13 occupy separate index ranges even when a reader considers them the same edition. Give each type one pair of inputs that become equal and one distinction that survives, wherever applicable. This would make the promise of reversibility concrete. [Type contracts](../README.md#supported-details) · [ISBN mapping](../nmr/types/identifiers.py) · [Tune identity](../doc/tunes.md)

6. **Completeness has several limits.** The default 1,627 words can form only finitely many nonrepeating names. Integers and strings have unbounded mathematical domains. Tunes also have computational and playback limits, so an object can have a name even when the browser cannot play it. Publish these as separate questions: can the type express my value, does its name fit, and can I hear it? An unsupported score and an invalid name call for different responses. [Vocabulary capacity and tune limits](../README.md) · [Projection tests](../test/test_tune_projection.py)

7. **An all-types clock is a particular sampling of the catalogue.** Root branches consume two low bits and each deeper branch consumes two more. The present DateTime mapping steps by three before zoot, which visits all four root residues over four seconds. A shallow leaf and a deep leaf still receive different shares, unassigned slots redirect during browsing, and playback skips seconds while a tune finishes. Before changing an enumeration, count the objects displayed and tunes actually selected separately, over a stated interval on each side of zoot. [DateTime mapping](../nmr/types/temporal.py) · [Routing](../nmr/category.py) · [Registry](../nmr/registry.py) · [Clock playback](../nmr/web/app.js)

## Questions for a first-time listener or recipient

8. **Can someone hear and repeat a useful name?** The word list and homophone checks address confusable words. They cannot establish whether a listener remembers a five-word sequence, preserves word order, or recognizes a plausible wrong answer. Try one spoken handoff each for a date, a coordinate and a phone number. Record exact recovery, requests for repetition and undetected mistakes alongside word count. [Vocabulary checks](../test/test_homophones.py) · [Example names](../test/format.json)

9. **Can someone tell what is sounding?** The live object can change every second while the score follows a longer phrase. The score and name can also remain after playback ends. Muted playback still advances. Try the same Clock task with sound on, muted, and using keyboard navigation at high zoom. Ask which object is live and which phrase is sounding. The existing desktop and mobile smoke checks establish layout properties but do not answer that question. [Playback help](../nmr/web/help.md) · [Browser checks](../test/browser_smoke.cjs)

10. **What does sharing reveal?** Conversion runs in the browser worker, but a shared or reloaded URL sends its query to the host. A reversible name for a phone number or home coordinate can disclose the value even when no digits appear in the URL. A first-time recipient also needs the hosted runtime assets for a cold start. Make the distinction between local conversion, opening a shared link, and decoding offline clear wherever a visitor is invited to share. [Browser deployment and privacy](../README.md#browser-tool) · [Worker startup](../nmr/web/worker.js)
